# 任务工作台 · 想法池 · 复盘

用 `tw_*` 工具读写当前工作区的任务清单，用 `tw_idea_*` 工具读写想法池；复盘（日/周/月）用 `tw_review_*` 工具**只读**。UI（侧栏「任务工作台」的「今日」「本周」「任务」「想法」四个 tab，今日页底部是复盘区）和 AI 用的是同一套 service、同一份 Markdown、同一套队列/备份/审计。

## 什么时候用

- 用户说「记一条任务 / 提醒我做 X / 明天要… / 加个待办」→ `tw_create`
- 用户问「今天要做什么 / 这周有什么 / 我有哪些任务」→ `tw_today` / `tw_week` / `tw_list`
- 用户说「把 X 改到周五 / 改成重要紧急 / 时间改成下午 3 点 / 备注写…」→ 先 `tw_list` 或 `tw_get_task` 找到 ID，再 `tw_update`
- 用户说「这个事从周三做到周五 / 改成跨周期任务」→ `tw_update` 或 `tw_create` 时传 `endDate`（和可选的 `endTime`）
- 用户说「删掉 X」→ 先找到 ID，确认是哪条，再 `tw_delete`（硬删除，有备份）
- 用户说「这个我完成了」→ **不要调用任何完成工具**（不存在）：告诉用户在任务工作台里勾选完成，由人确认。
- 用户说「记个想法 / 想法池：… / 帮我记一下这个想法」→ `tw_idea_create`
- 用户问「想法池里有什么 / 有哪些待实现的想法 / 找一下关于 X 的想法」→ `tw_idea_list`（可按状态 / 成熟度 / 关键词筛选）
- 用户说「把想法 X 的成熟度改成高 / 描述补一下 / 名字改一下」→ 先 `tw_idea_list` 或 `tw_idea_get` 找到 ID，再 `tw_idea_update`
- 用户说「删掉这个想法」→ 先找到 ID，确认名称，再 `tw_idea_delete`
- 用户说「把想法 X 标成推进中 / 完成 / 放弃」→ **不要调用任何改状态工具**（不存在）：告诉用户在想法列表里改状态，状态只能由人确认。
- 用户问「我上周复盘写了什么 / 最近几天的日复盘 / 上个月的月复盘 / 帮我看看我的复盘」→ `tw_review_list`（可按 daily / weekly / monthly 与 from / to 筛选），需要全文再 `tw_review_get`。
- 用户说「帮我写日复盘 / 补一个复盘 / 把复盘改成…」→ **不要写复盘**（没有写工具）：复盘内容必须由人在工作台写，AI 只能读。

## 任务类型与字段

- **当天任务**：只传 `date`。可选 `time`（HH:mm）；不传 `time` = 全天。
- **跨周期任务**：`date`（开始日期）+ `endDate`（结束日期，必须晚于开始日期）。可选 `time`（开始时间）、`endTime`（结束时间）；不传 = 当天/全天。
- 其他字段：`title`（≤200 字）、`priority`（重要紧急 / 重要不紧急 / 不重要紧急 / 不重要不紧急，默认重要不紧急）、`note`（单行，≤500 字）。
- `date`/`endDate` 用 `YYYY-MM-DD`；`time`/`endTime` 用 24 小时制 `HH:mm`。
- 标题/备注不能含全角分隔符 `｜` 或换行。
- 跨周期任务在起止日期内每天都会出现在「今日」；结束日期过了仍未完成 = 逾期。
- 本周视图里单日任务按日期落列，跨周期任务在区间内横跨显示。

## 想法池字段

- `name`（必填，≤200 字，禁 `｜`/换行）、`description`（可选，多行文本，≤10000 字）、`maturity`（低 / 中 / 高，默认低）、`category`（可选，单行，≤20 字）。
- 状态四选一：待实现 / 推进中 / 完成 / 放弃；新建默认「待实现」；进入「完成」会自动写完成日期，离开「完成」清除。
- 想法 ID 形如 `I-20261105-01`；想法池是**单文件、不按月切**，长期保留；列表默认按状态（待实现→推进中→完成→放弃）+ 更新日期倒序。
- **状态只能由人在面板里改**：AI 没有改状态工具；用户让你改状态时，说明在「想法」tab 里改。

## 复盘字段（只读）

- 三类：`daily`（日复盘，key = 日期）、`weekly`（周复盘，key = 该自然周的周一）、`monthly`（月复盘，key = `YYYY-MM`）。
- 周期口径：日复盘每天写今天；周复盘在周一至周日写上一个自然周；月复盘在当月最后一天（28/29/30/31 按实际）写本月，次月 1–3 日可补写。
- 数据文件：`复盘/日复盘.md`、`复盘/周复盘.md`、`复盘/月复盘.md`（单文件、不按月切）。
- AI 只能 `tw_review_list` / `tw_review_get`；**没有创建 / 修改 / 删除工具**，复盘正文只能由人写。用户让你写或改复盘时，说明在工作台「今日」页底部的复盘区写。

## 真源

`任务清单/YYYY-MM.md`（任务；当月分片可写，历史只读）、`想法池/想法池.md`（想法；单文件长期保留）与 `复盘/{日,周,月}复盘.md`（复盘；人写、AI 只读）。都在数据根下（默认 `$DSH_HOME/task-workbench/data`，不进 Git）。任务行示例：

```text
- [ ] `T-20261105-01`｜工作台开发｜日期：2026-11-05｜时间：09:30｜结束日期：2026-11-12｜结束时间：18:00｜优先级：重要紧急
```

想法行示例（详细描述写在想法行下面，2 个空格缩进；空行表示分段）：

```text
- `I-20261105-01`｜整理季度复盘｜状态：推进中｜成熟度：高｜分类：工作｜创建：2026-11-03｜更新：2026-11-06
  把本季度复盘材料整理成一份归档文档。
  先列大纲，再补数据。
```

## 工具规则

1. **先读再写**：不知道 ID 时先 `tw_today` / `tw_week` / `tw_list` / `tw_get_task`；不要猜 ID。
2. **直接写，不绕路**：AI 可以直接 create/update/delete（会记审计），不需要用户二次确认；但删除前应把任务标题说清楚。
3. **不要直接改 Markdown**：除非用户明确要求手工修文件/修格式；正常增删改一律走工具。
4. **完成/撤销是人的动作**：没有工具；不要声称「已帮你完成」。用户让你完成时，说明在工作台勾选即可。
5. **疑似重复**：`tw_create` 返回 `duplicate-suspected` 时，先问用户是否仍要创建；确认后带 `confirmDuplicate: true` 重试。
6. **失败不假装成功**：工具报错就把结构化错误和原因转告用户，不要自己编造任务 ID 或状态。
7. **日期缺省**：不传 `date` = 今天；用户说「明天/周五」时自行换算成 `YYYY-MM-DD`，不确定当前日期就先看 `tw_today` 返回的日期。
8. **改回当天任务**：`tw_update` 传 `endDate: ""`、`endTime: ""`；只清除时间传 `time: ""`。
9. **想法池先读再写**：不知道想法 ID 时先 `tw_idea_list` / `tw_idea_get`；不要猜 ID。
10. **想法状态仅人**：AI 没有改想法状态的工具，只能改名称 / 描述 / 成熟度 / 分类；用户让你改状态时，说明在「想法」tab 里点。
11. **删除想法前复述名称**：`tw_idea_delete` 是硬删除，有备份但面板内不可恢复。
12. **复盘只读**：`tw_review_list` / `tw_review_get` 是只读工具；不要声称帮用户写了复盘，也不要建议直接改复盘 Markdown（格式会被解析校验）。

## 常用示例

```text
用户：记一下，明天上午把周报发出去，重要不紧急
→ tw_create({ title: "把周报发出去", date: "<明天>", time: "09:00", priority: "重要不紧急" })

用户：记一个跨周期任务，工作台开发，11 月 5 号到 12 号
→ tw_create({ title: "工作台开发", date: "2026-11-05", endDate: "2026-11-12" })

用户：今天还有什么没做？
→ tw_today()

用户：把「约客户电话」改到周五
→ tw_list() 找到 ID → tw_update({ taskId, date: "<周五>" })

用户：把「工作台开发」改回只做一天
→ tw_update({ taskId, endDate: "", endTime: "" })

用户：这个任务我完成了
→ 不调用工具；回复：在任务工作台「今日」里勾选这条任务即可，完成只能由你确认。

用户：记个想法，工作台加一个想法池，先记着
→ tw_idea_create({ name: "工作台加想法池", description: "任务工作台里加想法管理池：编号、名称、描述、成熟度、状态。" })

用户：想法池里有哪些待实现的？
→ tw_idea_list({ status: "待实现" })

用户：把「工作台加想法池」的成熟度改成高
→ tw_idea_list() 找到 ID → tw_idea_update({ ideaId, maturity: "高" })

用户：把「工作台加想法池」标成推进中
→ 不调用工具；回复：在「想法」tab 里改状态，想法状态只能由你确认。

用户：我上周复盘写了什么？
→ tw_review_list({ kind: "weekly" }) 找到周期 → tw_review_get({ kind: "weekly", key: "2026-10-26" })

用户：帮我写今天的日复盘
→ 不调用工具；回复：复盘内容必须由你在「今日」页底部写，我只读。
```
