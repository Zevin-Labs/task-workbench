# 06 · 任务时间模型

> **状态：Phase 0 已实现并验收（2026-11-09，真实组件 + Chrome 15/15、定向测试 45/45）；§9 的时间切片匹配仍属下一阶段，未实现。**
> 目标读者：产品所有者、后续实现者；本文描述当前行为，并记录下一阶段设计边界。
> 2026-11-09 最终确认的产品口径：任务统一为**一个连续时间区间**（开始时间 → 截止时间，均含日期与整点时刻）；未填部分按默认规则补齐；类型由日期派生、不落库、不做选择；**不做「每日窗口」、不做「灵活/全天」标记**；下一阶段的时间切片匹配只读任务时间，不改任务时间。

## 1. 一句话模型

每个任务 = 连续时间区间 `startAt → endAt`：

- `startAt`：开始日期 + 开始小时（本阶段小时粒度）
- `endAt`：截止日期 + 截止小时
- 未填的日期/小时由默认规则补齐；补齐结果只在派生层体现，默认值不落库。
- 「当天 / 跨天」由 `endAt` 的日期是否晚于 `startAt` 的日期派生，不是字段、不是选项。

## 2. 默认值规则（用户已确认）

### 2.1 两个时间

| 名称 | 组成 | 默认 |
|---|---|---|
| 开始时间 | 开始日期 + 开始小时 | 今天 08:00 |
| 截止时间 | 截止日期 + 截止小时 | 开始日期 22:00（开始日期默认今天） |

小时粒度：`HH:00`，分钟固定 00；`14:30` 这类分钟值视为非法（未来需要分钟级时再放宽，schema 不用改）。

### 2.2 填写组合

| 用户填写情况 | 开始 | 截止 |
|---|---|---|
| 都不填 | 今天 08:00 | 今天 22:00 |
| 只填开始 | 用户值 | 开始日期 22:00 |
| 只填截止 | 今天 08:00 | 用户值 |
| 都填 | 用户值 | 用户值 |

更细的兜底顺序：

1. 开始日期未填 → 今天；开始小时未填 → 08:00。
2. 截止日期未填 → **开始日期**；截止小时未填 → 22:00。
3. 截止日期一旦由用户填写，必须是今天或之后的日期；截止时间必须晚于开始时间（完整时刻比较）。

> **对「截止日期不填默认今天」的解读**：开始日期默认今天，所以开始为今天时二者等价。但开始日期可能是未来（库里已有 11/12、11/15 的任务），若截止默认「今天」会得到截止早于开始、任务非法。因此实现按「截止未填 = 跟随开始日期」处理；若产品坚持字面「默认今天」，则未来日期的任务必须显式填截止日期（不建议）。

### 2.3 三种常见形态（只是派生结果，不是类型）

| 形态 | 开始 | 截止 | 说明 |
|---|---|---|---|
| 当天·默认时段 | 今天 08:00 | 今天 22:00 | 什么都不填时的默认 |
| 当天·指定时段 | 今天 14:00 | 今天 16:00 | 同一天，截止小时晚于开始小时 |
| 跨天 | 11/8 08:00 | 11/10 22:00 | 连续区间，跨多个自然日 |
| 跨午夜（跨天的一种） | 11/9 22:00 | 11/10 02:00 | 由日期+时刻比较天然支持，无需特殊规则 |

- 不显示「当天 / 跨天 / 灵活 / 全天」这类标签；界面上呈现的就是区间本身。
- 不做「每日窗口」：跨天任务不是「每天 14:00–16:00」，而是「从 11/8 08:00 连续到 11/10 22:00」。
- 不做「每天不同窗口」：未来匹配在人的时间切片里做，不改任务时间。

## 3. 校验规则

| 规则 | 说明 |
|---|---|
| 开始日期 | 可选，默认今天；允许过去日期（不做特殊处理）；允许未来日期（用于排期） |
| 开始小时 | 可选，默认 08:00；必须 `HH:00` |
| 截止日期 | 可选，默认开始日期；用户填写时必须 `>= 今天`；可等于开始日期（当天）或晚于（跨天） |
| 截止小时 | 可选，默认 22:00；必须 `HH:00` |
| 区间顺序 | `endAt > startAt`（完整时刻严格比较）；相等或倒置报错 |
| 同一天 | 截止小时必须晚于开始小时 |
| 跨天/跨午夜 | 不额外限制；`11/9 22:00 → 11/10 02:00` 合法 |
| 分钟 | 非 00 一律拒绝（本阶段只到小时） |
| 时长上限 | 不限制 |
| 标题 / 详情 | 沿用 01：标题单行简洁（≤200），详情多行（≤500，字段名 note） |

错误文案建议：

- `截止日期不能早于今天`
- `截止时间必须晚于开始时间`
- `时间只支持整点（分钟为 00）`
- `截止日期不能早于开始日期`

## 4. 存储与派生（不改 schema）

### 4.1 表结构不变

沿用 `tasks` 现有 4 列，不新增、不改名、不迁移、不回填：

| 列 | 语义（本模型） |
|---|---|
| `date` | 开始日期，`YYYY-MM-DD`，必填 |
| `time` | 开始小时，`HH:mm`（本阶段分钟恒为 00）；NULL = 未填 |
| `end_date` | 截止日期；NULL = 与 `date` 同日（当天任务）；有值时必须 `> date`（跨天） |
| `end_time` | 截止小时；NULL = 未填 |

- NULL = 用户未填；**不把默认值写进数据库**。
- `end_date == date` 在写入前归一化为 NULL，保证「有 end_date 必是跨天」这一现有不变量。
- 不存 `type`、不存 `duration`、不存任何「灵活/全天」标记。

### 4.2 唯一派生入口（建议新增到 `lib/core/contract.js`）

```js
export const DEFAULT_START_HOUR = '08:00'
export const DEFAULT_END_HOUR = '22:00'

// 返回：
// { startDate, startTime, endDate, endTime, crossDay,
//   startAt, endAt,       // 'YYYY-MM-DD HH:mm' 本地墙上时间
//   startMinutes, endMinutes }
export function effectiveInterval(task) { ... }
```

- UI、AI 工具输出、未来匹配器统一调用，不允许各自决定默认值。
- `publicTask` 增加派生字段 `startAt` / `endAt`（只读展示用），同时保留原始
  `date / time / endDate / endTime`（编辑预填与写入契约用）。

## 5. UI 交互

### 5.1 创建 / 编辑表单

字段顺序：

1. 标题
2. 详情
3. 开始日期（默认今天）
4. 开始小时（默认 08:00，下拉 00–23 整点，可清空）
5. 截止日期（默认跟随开始日期；用户手动改过后不再自动跟随）
6. 截止小时（默认 22:00，下拉 00–23 整点，可清空）
7. 优先级

- 小时控件只给整点，不提供分钟输入；清空表示使用默认值。
- 截止日期早于今天时直接不可选或即时提示；截止时间不晚于开始时间即时提示。
- 开始日期变化且截止日期未被用户手动修改时，截止日期自动跟随，避免「未来任务」被判非法。

### 5.2 派生摘要（让默认值可见）

表单底部灰字实时显示：

- `开始：今天 08:00 · 截止：今天 22:00`
- `开始：今天 14:00 · 截止：今天 16:00`
- `开始：11/8 08:00 · 截止：11/10 22:00（共 3 天）`

编辑态显示 `当前：…`；只显示区间，不显示「当天/跨天/灵活」标签。

### 5.3 列表与卡片

| 位置 | 显示 |
|---|---|
| 今日 | 当天任务：`08:00–22:00` 或 `14:00–16:00`；跨天任务：`11/8 08:00 → 11/10 22:00`，并按现有规则显示「第 X/Y 天」 |
| 本周 | 保持 2026-11-09 已确定的规则：日卡单日任务只显示任务名，不显示时间；跨天截止卡不变 |
| 总表 | 日期/时间列显示 `11/9 08:00 → 11/11 22:00`（当天任务显示 `11/9 08:00–22:00`） |
| 月历 | 不变（按日期落点、截止日标记） |
| 当天详情弹窗 | 显示完整开始/截止时刻；点任务进编辑，行为不变 |
| 复盘材料 | 不变（按日期范围与截止日列出） |

排序：同优先级内按 `startAt` 升序；今日视图仍保持「优先级优先」的现有口径。

## 6. 派生与视图影响（实现参考）

- `isRangeTask` 语义变为 `end_date > date`（跨天）；`taskEndDate` 不变（`end_date || date`）。
- `publicTask`：单日任务也返回 `endTime`；新增 `startAt` / `endAt`。
- `deriveToday` / `deriveWeek` / `deriveMonth` / `deriveCounts` 的判定逻辑不变，只调整展示。
- 跨天任务在今日的出现规则不变：`date <= today <= endDate`。
- 逾期：本阶段保留现有「按截止日期」口径（`taskEndDate < today`），不改成按截止时刻；是否改为 `endAt < now` 作为开放问题（§11）。
- 复盘材料不变。

## 7. AI 工具与技能

- **工具与字段不变**：`date`、`time`、`endDate`、`endTime`，不新增工具、不新增类型参数。
- 描述更新：开始/截止时间语义；时间留空默认 08:00/22:00；只支持整点；截止日期不填跟随开始日期、填了必须不早于今天；类型由日期跨度决定。
- 工具输出改为展示开始/截止时刻（如 `T-3｜11/8 08:00 → 11/10 22:00`）。
- 技能同步：字段规则、默认值、整点粒度、跨天即连续区间；示例补「当天 14:00–16:00」「11/8 08:00 → 11/10 22:00」。

## 8. 数据迁移与兼容

- **无 schema 迁移、无回填**。
- 现有 12 条任务的解释：
  - 7 条单日无时间 → 当天 08:00–22:00。
  - 5 条跨天无时间 → 首日 08:00 → 末日 22:00（连续区间）。
  - 1 条 20:45 的单日已完成任务 → 当天 20:45–22:00（仅展示变化）。
  - 现有 0 条 `end_time`，无历史语义冲突。
- 未来日期的任务（如 11/12、11/15）：开始 08:00、截止同日 22:00，不会因默认规则变非法。
- 旧版本插件与新版 host 混用不在支持范围；本机更新后按 docs/05 重启 DSH。

## 9. 下一阶段：时间切片与任务匹配（不在本阶段）

- 目标：把人的一天/一周/一周内每天切成时间片段（按精力特征），再把任务填进合适片段。
- 本模型提供：任务的连续区间、优先级、状态、稳定 ID `T-n`、`effectiveInterval` 唯一口径。
- 匹配器只读任务时间，**不回写任务时间**；某一天可用多少时间由「任务区间 ∩ 当天」派生，不落库、不是任务的属性。
- 本阶段不预建：精力/任务类型字段、切片模板表、任务-切片分配表、预估时长字段；等切片需求立项时用 `schema_version` 2 做加法迁移。
- 已知边界：不做每天不同窗口（不需要）；不做重复任务；不存时区；不做分钟级（先小时）。

## 11. 风险与开放问题

| 问题 | 现状/建议 |
|---|---|
| 截止日期默认「跟随开始日期」还是字面「今天」 | 按前者实现（否则未来日期任务非法）；本文件已注明，待最终确认 |
| 逾期按日期还是按截止时刻 | Phase 0 保留按日期，避免改变今日统计口径；切片阶段再评估 `endAt < now` |
| 卡片是否一直显示默认区间（08:00–22:00） | 建议今日/总表显示完整区间；本周卡维持只显示任务名（信息密度考虑） |
| 跨午夜（22:00 → 次日 02:00） | 由「日期+时刻」比较天然支持，不做特殊校验 |
| 历史 1 条 20:45 任务 | 展示变为 20:45–22:00，数据不动 |
| 默认值改了怎么办 | 派生层常量统一改，不涉及数据 |
| 日历导入导出 | Google 全天事件结束日排他，本模型包含式；未来对接需 ±1 天转换 |
| 分钟级需求 | 未来可放宽到 `HH:mm`，schema 已支持，无需迁移 |
| 时区/夏令时 | 只按本地墙上时间；中国无夏令时；不存时区 |
| 长期/无期限任务 | 当前不支持（每个任务都有日期区间）；不在本次范围 |
