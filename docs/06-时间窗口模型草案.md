# 06 · 时间窗口模型（草案）

> **状态：草案，待评审。本文不代表已实现，也不构成对当前行为的描述。**
> 目标读者：产品所有者、后续实现者。
> 2026-11-09 已确认的产品决策：① 任务只有三种形态（单日灵活 / 单日定时段 / 跨天每日窗口）；② 跨天任务采用「每日窗口」语义，不是连续区间；③ 先出设计、暂不改代码；④ 时间不填时按默认窗口解释，但默认值只做派生、不落库。

## 1. 背景与目标

### 1.1 现状

- 表单有一个「当天 / 跨周期」类型选择器；数据类型已由 `endDate > date` 派生（`isRangeTask`），选择器只是在替数据层做主。
- 单日任务：`date` + 可选 `time`；跨周期任务：`date + endDate`，可选 `time`（开始日时刻）与 `endTime`（截止日时刻）。
- 「时间」表达的是开始时刻；跨周期的 `endTime` 表达最后一天的截止时刻，不是每天的工作窗口。
- 下一阶段要按「天 / 一周 / 一周内每天」做时间切片，把不同精力片段与任务匹配。

### 1.2 目标

1. 任务统一为「日期区间 + 每日时间窗口」：每个任务都能解析出具体的开始/结束时刻。
2. 任务类型由日期区间派生，不再让用户选择。
3. 时间不填时，派生层默认使用 08:00–22:00 的正常日间窗口；**默认值不写进任务记录**。
4. 不改 schema、不改字段名、不做数据迁移；现有记录可直接按新语义解释。
5. 为时间切片模型保留清晰的扩展边界，但不预建任何表/字段。

### 1.3 非目标（本阶段明确不做）

- 时间切片模板、精力/任务类型匹配、自动排期分数（下一阶段单独立项）。
- 连续区间型任务/日历事件、跨午夜任务、每天不同时间窗、时区与夏令时处理。
- 任务预估时长、提醒、重复任务、拖拽改期。
- 新增任务字段、状态或 AI 工具。

## 2. 术语与三种形态

### 2.1 派生规则

```text
isRange     = endDate 存在且 endDate > date
singleDay   = !endDate 或 endDate == date
startTime   = time 合法 ? time : '08:00'
endTime     = endTime 合法 ? endTime : '22:00'
effective   = { startTime, endTime, explicitStart: time 有效, explicitEnd: endTime 有效 }
```

`endDate == date` 在写入前归一化为「无结束日期」，不落库；类型不写库，任何地方需要类型时现算。

### 2.2 三种形态（已确认）

| 形态 | 判定 | 示例 | 今日视图 | 有效窗口 |
|---|---|---|---|---|
| ① 单日·灵活 | 单日 + 时间都未指定 | 11/9「整理会议纪要」 | 只在 11/9 出现 | 08:00–22:00，标记「灵活」 |
| ② 单日·定时段 | 单日 + 指定了时间 | 11/9 14:00–16:00「投流复盘」 | 只在 11/9 出现 | 用户指定窗口（硬窗口） |
| ③ 跨天·每日窗口 | endDate > date | 11/9–11/11 每天 14:00–16:00 | 区间内每天出现 | 每天复用同一窗口 |

补充：

- 形态 ② 允许只填开始或只填结束：缺的一侧用默认值补齐（只填 14:00 = 14:00–22:00；只填 16:00 = 08:00–16:00）。
- 形态 ③ 的「结束时间」是**每天窗口的结束**，不是最后一天的截止时刻；这是相对当前实现的语义变化，见 §8。
- 「灵活」不是一个新字段或新类型，只是 `explicitStart/end` 都为 false 的派生结果。

### 2.3 为什么保留两种「未指定」语义

- 存储里 `time`、`endTime` 为空 = 用户没有指定，派生层解释为 08:00–22:00。
- 「未指定」和「显式指定 08:00–22:00」在下一阶段含义不同：前者是可放进任意合适片段的灵活任务，后者是硬窗口。
- 因此**不能**在保存时把默认值写进数据库，否则信息永久丢失。

## 3. 数据契约（不改 schema）

### 3.1 表结构

`tasks` 表保持现有列，不新增、不改名、不迁移：

| 列 | 类型 | 语义（本模型） |
|---|---|---|
| `date` | TEXT NOT NULL | 开始日期，`YYYY-MM-DD` |
| `time` | TEXT NULL | 每天窗口开始，`HH:mm`；NULL = 未指定 |
| `end_date` | TEXT NULL | 结束日期；NULL = 仅当天；有值时必须 `> date` |
| `end_time` | TEXT NULL | 每天窗口结束，`HH:mm`；NULL = 未指定 |

- 缺值统一存 `NULL`（与当前 Service 行为一致）；API 读出为 `null`，不是 `''`。
- 单日任务不存 `end_date`；`end_date == date` 属于非法存储形态，写前归一化。
- 不存 `type`、不存 `duration`、不存 `default_window`：全部派生。

### 3.2 唯一派生入口（建议新增到 `lib/core/contract.js`）

```js
export const DEFAULT_WINDOW_START = '08:00'
export const DEFAULT_WINDOW_END = '22:00'

// 返回 { startTime, endTime, explicitStart, explicitEnd, startMinutes, endMinutes }
export function effectiveWindow(task) { ... }

// 跨天任务的天数（含首尾）；单日为 1
export function taskDayCount(task) { ... }
```

- UI、AI 工具、未来匹配器都必须走这一个入口，禁止各自写一套默认值。
- 默认窗口先做成常量；将来要支持按工作日/周末或用户配置区分时，只改这一处，不动数据。

## 4. 校验与归一化规则

### 4.1 规则表

| 规则 | 当前行为 | 目标行为 |
|---|---|---|
| 开始日期 | 必填 | 必填，默认今天 |
| 结束日期 | 跨周期必填且必须 `> date` | 可选；`== date` 归一化为单日；`< date` 报错 |
| 开始时间 | 可选，单日只允许一个时间 | 可选，单日/跨天都允许 |
| 结束时间 | 只能和结束日期一起使用 | 可选，单日/跨天都允许；表示每天窗口结束 |
| 两时间都填 | 跨周期不校验先后 | 要求 `end_time > time` |
| 只填一个时间 | 跨周期可只填开始/结束 | 缺的一侧用默认值补齐（派生，不落库） |
| 跨午夜 | 不支持 | 仍不支持；`end_time <= time` 报错 |
| 每天不同窗口 | 不支持 | 仍不支持（未来单独设计） |
| 时区 | 本地墙上时间 | 不变；不存时区、不处理夏令时 |
| 标题 / 详情 | 见 01 | 不变（标题单行简洁，详情多行 ≤500，字段名 note） |

### 4.2 错误文案（建议）

- `结束日期不能早于开始日期；同一天请留空或用同一个日期`
- `结束时间必须晚于开始时间（跨午夜任务暂不支持）`
- `时间必须是 HH:mm（24 小时制）`
- `跨天任务每天使用同一时间窗口；如需每天不同，请拆成多条任务`（帮助文案，不是校验错误）

## 5. UI 交互

### 5.1 创建 / 编辑表单

字段顺序（替换现有「任务类型 + 日期/时间」区块）：

1. 标题
2. 详情
3. 开始日期（默认今天）
4. 开始时间（可选）
5. 结束日期（可选，提示「不填 = 仅当天」）
6. 结束时间（可选，提示「不填 = 22:00；结束时间须晚于开始时间」）
7. 优先级

布局建议：日期/时间两行两列（开始日期｜开始时间；结束日期｜结束时间），其余字段保持单列。

### 5.2 派生摘要（替代类型选择器，必须可见）

表单底部实时显示一行灰字，让隐式类型可见：

- `将创建：当天 · 11/9 · 14:00–16:00`
- `将创建：当天 · 11/9 · 灵活时段（08:00–22:00）`
- `将创建：跨天 · 11/9–11/11 · 每天 14:00–16:00（3 天）`
- `将创建：跨天 · 11/9–11/11 · 每天灵活时段（08:00–22:00，3 天）`

编辑态显示 `当前：…`，并在修改日期/时间时实时更新。

### 5.3 校验时机

- 提交时校验并定位到第一个错误字段；结束日期早于开始日期、结束时间不晚于开始时间时即时提示。
- 编辑旧任务时按现有字段预填；旧任务没有时间 → 显示为空（不预填 08:00/22:00），摘要按默认窗口展示。

### 5.4 列表与卡片展示

| 位置 | 显示 |
|---|---|
| 今日 | 显式窗口显示 `14:00–16:00`；未指定显示「灵活时段」或不显示时间（保持列表干净，推荐「灵活」弱化标签）；跨天显示 `每天 14:00–16:00 · 第 2/3 天` |
| 本周 | 保持 2026-11-09 已确定的规则：日卡单日任务只显示任务名；跨天截止卡不变 |
| 总表 | 日期/时间列显示 `11/9–11/11 · 每天 14:00–16:00`；灵活任务显示「灵活时段」 |
| 月历 | 不变（按日期落点与截止日标记） |
| 当天详情弹窗 | 显示完整窗口 + 是否灵活；点任务进编辑，行为不变 |
| 复盘材料 | 不变（仍按日期区间和截止日列出） |

排序口径：未指定时间的任务仍归入「全天/灵活」组（排在显式时间之前，沿用现有 `compareTime` 的空值在前规则）；显式时间按开始时间排序。

## 6. 派生与视图影响（实现参考）

- `publicTask`：`endTime` 不再只对跨周期暴露，单日也返回；`time`/`endDate` 的 null 语义不变。
- `isRangeTask` / `taskEndDate` / `deriveToday` / `deriveWeek` / `deriveMonth` / `deriveCounts`：判定逻辑不变，只调整展示字段。
- 跨周期任务在今日的出现规则不变：`date <= today <= endDate`。
- 逾期判定不变：`taskEndDate < today`。
- `rangeProgress` 已提供「第 X/Y 天」，可直接复用到窗口展示。
- 不新增派生字段到 API；需要窗口的消费者调用 `effectiveWindow(task)`（UI 可内联，host/AI 走 core）。

## 7. AI 工具与技能

- **工具与字段不变**：仍是 `date`、`time`、`endDate`、`endTime`，不新增工具；`note` 仍是详情。
- 工具描述更新为：时间留空 = 默认 08:00–22:00 窗口；结束时间可单日或跨天，表示每天窗口结束；跨天任务每天复用同一窗口；类型由日期跨度决定，不需要传类型。
- 技能说明同步：三种形态、默认窗口、跨天每日窗口、结束日期留空 = 当天；`tw_create` / `tw_update` 示例补一条单日定时段和一条跨天窗口。
- 校验失败仍返回明确结构化错误，不假装成功。

## 8. 数据迁移与兼容

- **无 schema 迁移、无数据回填**：现有 12 条任务全部可解释。
  - 11 条无时间任务 → 按默认窗口（08:00–22:00）解释，记录不变。
  - 1 条带 `20:45` 的单日已完成任务 → 语义从「20:45 开始」变为「20:45–22:00 窗口」，仅展示层变化。
  - 当前 0 条 `end_time` 记录，所以「最后一天截止时刻 → 每天窗口结束」的语义切换**没有历史数据成本**。
- 现有数据里没有 `end_date == date` 的脏数据；新校验仍会在写入前归一化。
- 不把默认窗口写进旧记录；不新增列。
- 旧版本客户端/插件与新版 host 混用不在支持范围；本机更新后按 docs/05 重启 DSH。

## 9. 下一阶段时间切片（预留，不在本阶段实现）

### 9.1 本模型已提供

- 每个任务可解析出：`开始日期`、`结束日期`、每天窗口、显式/灵活标记、优先级、稳定 ID `T-n`、状态与完成日。
- `effectiveWindow` / `taskDayCount` 可作为匹配器唯一时间口径。

### 9.2 下一阶段才需要、现在不预建

| 需要 | 形态 | 备注 |
|---|---|---|
| 任务精力/类型标签（脑力 / 事务 / 视频 / 休息…） | 任务新增字段（枚举或标签） | 采用加法迁移，`schema_version` 升级；现在不建 |
| 人的一周切片模板 | 新表：星期 × 时间窗 × 精力类型 | 与任务表分离 |
| 任务与切片/日期分配 | 新表：任务 × 日期 × 窗口分配 | 支持一个任务跨多天分配 |
| 预估时长 | 任务新增字段 | 可选；窗口长度可先替代 |

### 9.3 已知限制（未来设计时要处理）

- 只支持「每天同一个窗口」；每天不同窗口需要按天排期表。
- 不支持跨午夜（22:00–02:00）；如果以后要支持，需要单独定义窗口形状，不能靠 `end_time <= time` 猜。
- 不存时区；跨时区使用时需要重新设计。
- 默认窗口是「灵活」而不是「占满 08:00–22:00」；匹配器必须读 `explicitStart/end`，否则会把灵活任务当成 14 小时硬占用。
- 日历互操作注意：Google Calendar 的全天事件结束日期是排他的（次日），本模型是包含式，导入导出需要 ±1 天转换。

## 11. 风险与开放问题

| 风险 | 缓解 |
|---|---|
| 默认窗口被误当硬占用 | 存 NULL + 显式/灵活标记；匹配器必须读标记 |
| 用户忘填结束日期 → 静默变当天 | 表单摘要实时显示派生类型 |
| 跨天任务每天重复出现造成今日列表膨胀 | 沿用「进行中 · 第 X/Y 天」弱化展示；后续可考虑折叠 |
| 「结束日期」被理解成纯 deadline | 文案用「结束日期」而非「截止日期」；如需真正 deadline，另立字段，不与窗口混用 |
| 跨午夜/每天不同窗口暂时无法表达 | 文档写清限制；需要时拆任务或后续扩展 |
| 日历导入导出差一天 | 未来对接时统一做包含式/排他式转换 |
| 默认窗口 08:00–22:00 是否合理 | 先作为核心常量；将来可配置，但不动数据 |

开放问题（评审时定）：

1. 默认窗口是否固定 08:00–22:00，还是按工作日/周末不同？（建议先固定，派生层留配置入口）
2. 「灵活」任务在今日列表里怎么显示最不吵？弱化标签 / 不显示 / 归入「全天」组。
3. 单日任务只填结束时间（如 16:00）时，开始默认 08:00 是否符合直觉？
4. 跨天任务是否允许用户分别设置开始日与结束日的时间（即首个窗口与前几个窗口不同）？当前视为同一窗口。
