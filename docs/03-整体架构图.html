任务工作台 · 当前架构

本机单用户插件。一个 SQLite 数据库是任务、想法和复盘的唯一真源；界面与 AI 通过同一组领域 Service 读写。

版本说明：当前已发布版本 0.6.0 使用 SQLite；0.5.0 是历史 Markdown 版本。当前代码不读取或导入旧版 Markdown；首次初始化建立空数据库。

使用入口

UI：原生 React → 本机同源 /tw/api

AI：14 个既有工具 → 各自领域 Service

任务 7想法 5复盘只读 2
→

领域 Service

TaskService · IdeaService · ReviewService

统一校验、权限、baseVersion、审计和错误返回。

UI 与 AI 不绕过 Service 访问数据库。

→

本机 SQLite

Node 内置 node:sqlite DatabaseSync

默认数据根内的 workbench.sqlite

同步短事务，提交或回滚业务写入。

数据库表

tasks

稳定序号 ID

标题、日期/时间区间、优先级、完成状态、备注

ideas

稳定序号 ID

名称、描述、状态、成熟度、分类、日期

reviews

类型 + 周期键

正文、更新时间；历史查询只读

write_log

业务写入审计

操作、领域、目标、actor、细节

meta

内部元数据

schema_version 与领域版本号

事务与冲突

每次写入在短事务内更新业务数据、审计行和领域版本号；任一步失败则回滚。

UI 带 baseVersion 防止陈旧页面覆盖较新的数据。AI 可省略版本号。

快照备份

硬删除任务、删除想法、清空复盘前创建 SQLite 快照并校验完整性与目标记录。

默认保留 7 天；backupRetentionDays 可设置 1–90 天。

人机权限

任务完成/撤销、想法状态流转、复盘正文只由人操作。

AI 可管理任务与想法内容，复盘只有读取工具。

历史语义

跨月任务仍是同一条记录；过月已完成任务只读。

复盘按类型和周期键存储，历史入口只读；现有日期窗口不变。

未来扩展边界

未来时间块匹配、人与 AI 协作沿用稳定任务 ID 和领域 Service。当前不增加预留字段、表、工具或执行状态机；具体需求确认后再扩展。

数据根默认 DSH_HOME/task-workbench/data；settings.json 仅保存 dataRoot 与 backupRetentionDays。SQLite 版本不导入旧版 Markdown。
