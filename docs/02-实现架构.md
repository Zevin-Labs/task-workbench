# 02 · 实现架构

> 本文记录当前实现。已发布 npm 0.5.0 是历史 Markdown 版本；当前唯一数据真源为数据根中的 workbench.sqlite。
> 当前产品边界和用户可见口径见 [01 功能规格](./01-功能规格.md)。协作和测试见 [05](./05-协作与测试.md)。

## 1. 架构原则

1. **单机单库**：一个用户、一个本地 Host 进程、一个 SQLite 文件；不引入服务端、多用户同步或后台进程。
2. **统一读写入口**：UI 和 AI 分别经本机 HTTP 路由和 Agent 工具调用任务、想法、复盘 Service；Service 使用同一个数据库对象。
3. **事务边界简单明确**：同步短事务在 SQLite 内原子提交业务行、write_log 审计和对应领域版本。SQLite 负责事务串行化，不再使用按域异步队列、文件 hash、临时文件替换或写后回读。
4. **现有权限不变**：任务完成/撤销、想法状态、复盘正文只有人可以写；AI 只能通过既有工具操作允许的字段。
5. **不预建未来产品**：时间块与人与 AI 协作只沿用稳定业务 ID 和领域 Service 入口。本版不增加字段、表、工具或空壳抽象。

## 2. 数据位置与初始化

- 数据根默认是 DSH_HOME/task-workbench/data；settings.json 的 dataRoot 可覆盖。
- 数据库文件为 dataRoot/workbench.sqlite。插件安装在 link、本地目录、tarball 或 npm 包时，数据路径保持独立，不放进 node_modules。
- settings.json 只保留 dataRoot 和 backupRetentionDays。初始化状态从数据库文件与 schema 检查得出；不保存 initialized、ID 水位或审计日志。
- 第一次初始化显式创建空数据库。旧版 Markdown 不扫描、不导入、不迁移；已发布的 0.5.0 数据格式不再是运行时输入。旧版测试数据已经私下归档，不在公开文档记录机器路径。
- Node 要求 >=24，使用内置 node:sqlite DatabaseSync；无 SQLite 包、ORM、运行时服务或构建步骤。

## 3. SQLite schema

数据库只含三个业务表、一个审计表与一个内部元数据表。字段名以下划线形式存储，Service 转成前端/工具使用的 camelCase。

| 表 | 主键 | 主要字段 | 用途 |
|---|---|---|---|
| tasks | 自增 id | title, date, time, end_date, end_time, priority, done, completed, note | 单条任务记录；跨月不会复制或分片 |
| ideas | 自增 id | name, description, status, maturity, category, created, updated, completed | 想法池 |
| reviews | kind + period_key | text, updated_at | 日/周/月复盘；周期类型和周期键唯一 |
| write_log | 自增 id | at, actor, actor_kind, op, domain, target, detail | 业务写入审计 |
| meta | meta_key | value | schema_version 与各领域版本号 |

### 3.1 ID 和周期键

- 任务 ID 由数据库自增序号表现为 T-n；想法 ID 表现为 I-n。使用 AUTOINCREMENT，删除后不复用。
- 复盘 ID 是复盘类型和周期键的组合，不另造序号：日=日期、周=自然周周一、月=YYYY-MM。
- 未来若任务域或想法域要跨模块引用，使用现有稳定 ID；不要现在加入预留列。

### 3.2 日期读取口径

- 今日、本周通过任务日期范围查询同一 tasks 表；跨周期任务保留开始/结束日期。
- 总表默认取全部未完成任务；含已完成时补充本月完成记录。
- 跨月未完成任务始终是同一行。任务完成的次月，其历史记录保留且只读。
- 周/月复盘材料对 tasks 和 reviews 按自然日期范围查询，不拼接或复制月度文件。

## 4. Host、Client 与职责

- lib/index.js：装配数据库、三个 Service、路由、14 个 Agent 工具和技能 Provider。
- lib/client.js：原生 React UI，通过同源本机 /tw/api 请求；不直接接触 SQLite。
- lib/core/：任务/想法/复盘的字段校验、日期计算、列表派生与复盘窗口等纯函数。
- lib/host/db.js：Node SQLite 连接、初始化、schema 检查、短事务、领域版本、审计、快照备份。
- lib/host/service.js：TaskService；lib/host/idea-service.js：IdeaService；lib/host/review-service.js：ReviewService。
- lib/host/routes.js 及各领域 routes：本机 UI API；各领域 tools：AI 对 Service 的工具封装。
- lib/host/gateway.js 只负责错误归一化和进程内 requestId 幂等缓存，不管理队列或数据库写入。
- skills/task-workbench/SKILL.md 说明工具调用和权限，不构成另一条写路径。

UI 和 AI 操作同一业务数据；数据库操作只在 Host Service 边界发生。

## 5. 写入一致性

每个 Service 完成字段校验与权限校验后，在同步短事务中执行：

1. BEGIN IMMEDIATE，SQLite 获取写事务。
2. 检查调用方提供的 baseVersion 是否与对应域当前版本一致；不一致则返回 external-change。
3. 执行业务 INSERT / UPDATE / DELETE。
4. 同一事务插入 write_log 审计行并增加对应域版本号。
5. COMMIT；任一步失败就 ROLLBACK。

baseVersion 按领域独立维护：tasks、ideas、review:daily、review:weekly、review:monthly。UI 提交版本以拒绝陈旧表单覆盖新数据；AI 工具仍可省略 baseVersion。requestId 只用于短期进程内幂等，不作为数据真源。

错误不能吞掉或伪装成功。UI 与工具收到 service 的结构化错误码，例如 validation-error、permission-denied、not-found、external-change、history-readonly、backup-failed 或 write-failed。

## 6. 删除与备份

硬删除任务、硬删除想法、清空复盘之前生成 SQLite 一致性快照：

- 使用 SQLite VACUUM INTO 创建快照，再用只读连接执行 integrity_check，并确认待删目标确实存在于快照。
- 快照写入 dataRoot/备份/YYYY-MM-DD/，文件扩展名为 .sqlite；原因区分 tasks、ideas、reviews。
- 校验失败时中止删除或清空，并返回 backup-failed。
- backupRetentionDays 保持可配置；默认 7 天，限制为 1–90 天。清理只处理本版本的 SQLite 快照，不主动删除其他内容。
- 普通新增、编辑、完成/撤销不创建整库快照。

## 7. HTTP 与 AI 工具契约

UI 使用 loopback 且同源的 /tw/api：

- 任务：/bootstrap、/today、/week、/tasks、/tasks/:id、/tasks/:id/complete、/init、/settings、/reload。
- 想法：/ideas、/ideas/:id。
- 复盘：/reviews、/reviews/:kind/:key；GET 可读取历史正文，写入仍受窗口和权限控制。
- API 只转发到 Service，不能直接拼 SQL 或另写文件。

AI 工具保持现有 14 个，不增加历史工具或未来协作工具：

| 域 | 工具 | 权限 |
|---|---|---|
| 任务（7） | tw_today, tw_week, tw_list, tw_get_task, tw_create, tw_update, tw_delete | 可读；可创建/编辑/删除；没有完成/撤销工具 |
| 想法（5） | tw_idea_list, tw_idea_get, tw_idea_create, tw_idea_update, tw_idea_delete | 可读；可创建/编辑内容/删除；没有状态修改工具 |
| 复盘（2） | tw_review_list, tw_review_get | 只读 |

Server 端同样执行权限校验，工具列表不是唯一安全边界。

## 8. 复盘历史读取

ReviewService 提供按类型和周期范围的列表/摘要读取，以及单条完整正文读取。今日页的轻量周期回查只读这些接口，不绕过 Service、不直接打开文件，也不改变复盘可写窗口。

历史日/周/月复盘继续只读；写操作只有当前产品规则允许的窗口。日、周、月日期计算仍由 core/review-window.js 维护。

## 9. 未来扩展边界

规划中的高效时间块匹配、人与 AI 协作登记与审核尚未实现。本架构只要求：

- 任务、想法保持稳定 ID；新的关系需通过 Service 表达。
- 前端、AI 和其他模块继续复用相同 Service，不能另开数据库写入口。
- 新功能经过单独产品设计与确认后再决定字段和表；不为“可能会做”先加通用任务类型、预留 JSON、事件框架或 agent 状态机。

## 10. 测试与验收

测试规则与文件映射以 [05 协作与测试](./05-协作与测试.md) 为准。

- 任务改动：npm run test:task。
- 想法改动：npm run test:idea。
- 复盘改动：npm run test:review。
- 读写层、装配、设置或技能改动：按 05 矩阵跑相关定向测试。
- 数据 schema / 跨域共享改动：说明影响后最多跑一次全量 npm test。
- 测试只用 os.tmpdir() 下的临时数据库，不访问真实数据根。

真实环境验收应检查初始化为空库、任务/想法/复盘端到端读写、baseVersion 冲突、权限边界、硬删除快照和历史复盘只读入口。动真实数据前先备份 SQLite 文件，验收后恢复原状。
