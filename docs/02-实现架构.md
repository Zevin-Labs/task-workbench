# 实现架构（V3.0）

> 阶段：**V3.0 已实现、已安装、已验收**（2026-11-05：新增日/周/月复盘——独立数据域、三个单文件、可写窗口、周/月材料、AI 只读）。本文记录实际实现，不是待开发设计稿。
> 上游功能规则：[01 功能规格](./01-功能规格.md)；整体图：[03 整体架构图](./03-整体架构图.html)；架构图：[acceptance/架构图.png](./acceptance/架构图.png)。
> 原则：**最小可交付**。没列进本文的能力一律不做。

## 0. 一页结论

### 0.1 V3.0 做什么

| 能力 | 实现 |
|---|---|
| 今日视图 | 逾期未完成 + 今天要做（含进行中的跨周期任务）+ 今天已完成（可撤销） |
| 本周视图 | 自然周（周一→周日）7 列；单日任务按日期落列；跨周期任务在顶部摘要条显示（悬停 chip 高亮对应日期列） |
| 任务总表 | 当月任务，前端筛选关键词/状态/优先级；显示日期/时间/区间 |
| 任务类型 | 当天（单日）或跨周期（开始日期 → 结束日期）；时间可选，缺省 = 全天 |
| 任务创建 / 编辑 / 删除 | 行级增删改；删除为**硬删除**（二次确认 + 写前备份） |
| 任务完成 / 撤销完成 | 勾选 / 取消勾选（**仅人**；AI 无完成工具） |
| 想法池 | 列表 + 状态统计筛选 + 搜索/成熟度/分类/排序；卡片、新建/编辑/删除弹窗 |
| 想法字段 | 编号 `I-YYYYMMDD-NN`、名称、多行详细描述、状态四态、成熟度三档、分类（可选）、创建/更新/完成日期 |
| 想法状态 | 待实现 / 推进中 / 完成 / 放弃；**状态仅人改**，AI 无改状态工具 |
| 想法存储 | `data/想法池/想法池.md` 单文件、不按月切；首次写入自动建文件 |
| 复盘（日/周/月） | 今日页「今天已完成」之后的复盘区：日复盘每天写今天；周复盘本周内复盘上一自然周；月复盘当月最后一天写本月（次月 1–3 日可补写） |
| 复盘窗口 | 服务端强制可写窗口：日=今天 / 周=本周一→周日 / 月=月末最后一天→次月 3 日；窗口外写入 400 |
| 复盘字段 | 周期键（日=日期 / 周=该周周一 / 月=`YYYY-MM`）、正文（多行纯文本 ≤20000 字）、更新时间；无 ID |
| 复盘存储 | `data/复盘/日复盘.md`、`周复盘.md`、`月复盘.md` 三个单文件、不按月切；首次写入自动建文件 |
| 复盘材料 | 周块=上周任务概况 + 上周日复盘；月块=本月任务概况 + 本月周复盘；跨月只读合并相邻月分片 |
| 复盘权限 | 正文只能由人写；AI 只有 `tw_review_list` / `tw_review_get` 只读工具 |
| AI 读写 | 任务 `tw_*`、想法 `tw_idea_*`；分别走 TaskService / IdeaService，共用同一写网关（队列/幂等/审计） |
| 外部改动 | UI 每 5 秒轮询 bootstrap + 当前视图；写入前 `baseHash` 检测，冲突拒绝覆盖 |

**技术形态**：DSH Cordis 双半插件（host + client）。Host 用 `node:fs` 读写 Markdown；Client 是手写 lazy-CJS 的原生 React 主面板，无构建步骤、不用 iframe。

### 0.2 V3.0 不做什么（明确边界）

- 不扫描任何知识库或外部文档系统；不做固定动作规则、项目/方向、标签/子任务/附件。
- 不做项目/方向三轴、周期任务（重复规则）、农历/调休。
- 不做应用内提醒、系统推送；不做 Dock 数字徽章；想法「已放置 N 天」只是展示。
- 不做 AI 认领 / 待验收 / 人工验收 / 建议卡；不做旧数据迁移或导入。
- 不做任务归档/取消状态；不做回收站。
- 不做历史月份浏览（历史分片只读，任务工作台只加载当月）。
- **不做想法 → 任务转化**、想法看板、想法归档/容量上限/自动清理。
- **不做复盘历史浏览 tab / 复盘统计图表 / 补写更早周期**；周只提示上一个自然周，月只在次月 1–3 日可补。
- **不做 AI 写复盘**（无写工具；service 对非 user actor 拒绝）；复盘不做提醒推送、不做「打卡」。
- 想法与任务不共用一张表：任务按月分片，想法单文件长期保留（理由见 §1.8 / §10）。

> 范围冲突时以 §0.2 为准；新增能力另开版本。

## 1. 数据契约

### 1.1 数据根与分片

- **数据根**：默认 `$DSH_HOME/task-workbench/data`（`DSH_HOME` 缺省 `~/.dsh`），可由 `settings.json` 的 `dataRoot` 覆盖。**与安装形态解耦**：`link:`、本地目录、tarball、npm 包都写同一处，升级/重装不会把数据写进 `node_modules` 副本。本地开发可把 `dataRoot` 指到仓库内 `data/`。不进 Git；可整体拷贝备份/迁移。
- **任务按月分片**：`data/任务清单/YYYY-MM.md`；**当月分片唯一可写**，历史分片只读。
- **想法单文件**：`data/想法池/想法池.md`；**不按月切**，长期保留；文件不存在时首次写入自动创建。
- **备份**：写前备份到 `data/备份/<YYYY-MM-DD>/任务清单-<YYYY-MM>-<HHMMSS>.md` 或 `想法池-<HHMMSS>.md`，默认保留 7 天（`settings.backupRetentionDays` 可设 1–90）。
- **当月判定**：本机本地时区 `YYYY-MM`；任务分片不存在时按 §1.6 月切。

```text
data/
├── 任务清单/
│   ├── 2026-11.md          # 当月任务分片：唯一可写
│   └── 2026-10.md          # 历史任务分片：只读
├── 想法池/
│   └── 想法池.md           # 想法单文件：长期保留、不按月切
└── 备份/2026-11-05/
    ├── 任务清单-2026-11-165208.md
    └── 想法池-210633.md
```

### 1.2 分片骨架（两块）

```markdown
---
title: 任务清单 2026-11
type: task-list
format: 1
month: 2026-11
created: 2026-11-01
updated: 2026-11-05
---

# 任务清单 · 2026-11

## 任务

- [ ] `T-20261105-01`｜写周报｜日期：2026-11-05｜时间：09:30｜优先级：重要不紧急｜备注：只写结论
- [ ] `T-20261104-02`｜约客户电话｜日期：2026-11-06｜优先级：重要紧急
- [ ] `T-20261105-03`｜工作台开发｜日期：2026-11-05｜时间：09:30｜结束日期：2026-11-12｜结束时间：18:00｜优先级：重要紧急

## 已完成

- [x] `T-20261104-01`｜整理会议纪要｜日期：2026-11-04｜优先级：重要不紧急｜完成：2026-11-04
```

- 只有两个 H2：`## 任务`（待办）、`## 已完成`（`[x]` + 完成日期）。
- 区块缺失/重复 → `parse-error`（只读并提示修复）；未知 H2/未知行原样保留，写入器只动目标行，不整文件重排。
- UTF-8（无 BOM）、LF；frontmatter `format: 1`（缺失或 >1 只读）。
- 其他非任务行（例如标题下的说明引用）原样保留；测试里已覆盖。

### 1.3 任务行语法

```text
task_line = "- [" SP? (" "|"x"|"X") SP? "] " "`" id "`" "｜" title ( "｜" field )*
id        = "T-" 8DIGIT "-" 2DIGIT
field     = key "：" value
key       = "日期" | "时间" | "结束日期" | "结束时间" | "优先级" | "备注" | "完成" | 未知键（原样保留）
```

- 分隔符是全角 `｜`（U+FF5C）；标题与字段值内禁止 `｜` 和换行。
- ID 用反引号包裹、紧跟复选框；严格匹配 `T-YYYYMMDD-NN`。
- `- [X]` 读入视为 `[x]`，写回统一小写。
- 未知键（如 `其他：x`）与无法识别的片段在读取时保留、写回时追加在行末。

### 1.4 字段表

| 字段 | 键/位置 | 必填 | 取值 | 缺省 | 说明 |
|---|---|---|---|---|---|
| ID | 第 1 段反引号 | 是 | `T-YYYYMMDD-NN` | — | 创建日 + 当日序号；当月内不复用（含删除后） |
| 标题 | 第 2 段 | 是 | 文本 | — | 禁 `｜`/换行；≤ 200 字 |
| 日期 | `日期：` | 是 | `YYYY-MM-DD` | — | **开始日期**：当天任务就是任务日期；跨周期任务是区间起点 |
| 时间 | `时间：` | 否 | `HH:mm`（24 小时制） | 空 = 全天 | 当天任务的执行时间；跨周期任务的开始时间 |
| 结束日期 | `结束日期：` | 否 | `YYYY-MM-DD`，必须晚于日期 | 空 = 当天任务 | 有合法结束日期即视为跨周期任务；今日=区间覆盖今天，逾期=结束日期已过 |
| 结束时间 | `结束时间：` | 否 | `HH:mm`（24 小时制） | 空 = 全天 | 跨周期任务的结束时间；必须与结束日期同时出现 |
| 优先级 | `优先级：` | 否 | 重要紧急 / 重要不紧急 / 不重要紧急 / 不重要不紧急 | 重要不紧急 | 四选一；默认值不写字段 |
| 状态 | 不落字段 | — | 待办 / 已完成 | 待办 | `[ ]`=待办，`[x]`=已完成（避免双真源） |
| 备注 | `备注：` | 否 | 单行文本 | 空 | ≤ 500 字 |
| 完成日期 | `完成：` | `[x]` 时必填 | `YYYY-MM-DD` | — | 完成时写入；缺失只提示，不编造 |

**ID 不复用**：`$DSH_HOME/task-workbench/ids.json` 记录每天已分配到的最大序号；创建时取「状态文件记录」与「文件内已有 ID」的最大值 +1，删除任务后再建也不会复用。状态文件丢失时退化为按文件扫描（极端情况可能复用，可接受）。

### 1.5 完成、撤销与删除

- **完成（仅人）**：同一次原子写里写 `[x]` + `完成：<今天>`，把行从 `## 任务` 移入 `## 已完成`。
- **撤销完成（仅人）**：去掉 `[x]`、删除 `完成：`，把行移回 `## 任务`（追加到区块末尾）；日期不变。
- 完成/撤销只动目标行及其位置，其他行逐字节不变；只在当月分片内可用。
- **删除 = 硬删除**：从区块移除该行；写前备份；无归档、无取消、无回收站；任务工作台内不可恢复（可从备份手工恢复）。

### 1.6 月切（分片生命周期）

- **触发**：每次读写前检查 `data/任务清单/<当月>.md` 是否存在；不存在则月切。
- 数据目录未初始化（无任何分片且设置未标记）→ `file-missing`，UI 显示初始化入口。
- 已初始化 → 取**月份 < 当月的最新分片**为来源，创建当月分片：
  1. 生成两块空骨架；
  2. 把来源 `## 任务` 中未完成行逐字节复制（含未知字段）；
  3. `## 已完成` 不结转，留在历史分片；
  4. 原子写 + 回读校验；
  5. 失败 → `rollover-failed`，进入只读并提示重试。
- 月切是唯一跨文件写；之后旧分片永久只读。

### 1.7 校验与容错

**写入前校验**（`validation-error`）：标题非空、无 `｜`/换行、≤200；日期合法；时间 `HH:mm`；结束日期合法且晚于开始日期；结束时间必须伴随结束日期；优先级枚举合法；备注单行、无 `｜`、≤500；ID 格式合法且当月唯一。

| 读取情况 | 行为 |
|---|---|
| 未知字段 / 未知 H2 / 非任务行 | 原样保留，不报错 |
| 字段值非法 | 保留原行，标记 warning，按缺省投影 |
| `[x]` 无 `完成：` | 视为已完成并 warning |
| 区块缺失/重复 | `parse-error` 只读 |
| `format` 缺失或 ≠1 | 只读，提示格式不受支持 |

容错原则：能读就读、能保留就保留、不能理解就不猜；只读模式绝不写入。

### 1.8 想法池数据契约（V2.0 新增）

**文件**：`data/想法池/想法池.md`；单文件、不按月切；`type: idea-pool`、`format: 1`。文件不存在 = 空池；首次写入前自动创建骨架（`IdeaStore.ensureFile`，数据根未初始化时拒绝）。

```markdown
---
title: 想法池
type: idea-pool
format: 1
created: 2026-11-05
updated: 2026-11-05
---

# 想法池

> 零摩擦捕获；状态与成熟度由人维护，定期整理。

## 想法

- `I-20261105-01`｜整理季度复盘｜状态：推进中｜成熟度：高｜分类：工作｜创建：2026-11-03｜更新：2026-11-06
  把本季度复盘材料整理成一份归档文档。

  先列大纲，再补数据。

- `I-20261105-02`｜工作台加想法池｜状态：待实现｜成熟度：中｜创建：2026-11-05｜更新：2026-11-05
```

**行语法**

```text
idea_line    = "- `" id "`" "｜" name ( "｜" field )*
id           = "I-" 8DIGIT "-" 2DIGIT
field        = key "：" value
key          = "状态" | "成熟度" | "分类" | "创建" | "更新" | "完成" | 未知键（原样保留）
description  = 想法行之后、以 2 个空格开头的连续行（空行写成 2 个空格，表示分段）
```

- 只有一个 H2：`## 想法`；区块缺失/重复 → `parse-error` 只读。
- 想法行必须在第 0 列；描述行固定 2 空格缩进，空行结束描述块（块间用一个空行分隔）。
- 描述行内容可含 `｜`、`#`、`- ` 等（缩进后不会被误解析为字段/标题/新想法）；写回时统一 2 空格缩进。
- 状态/成熟度非法 → warning + 按默认值投影；创建/更新日期非法 → warning + 回退（ID 日期 / 创建日期）；状态=完成但缺完成日期、或非完成状态带完成日期 → warning。
- 未知字段、无法识别的列 0 行原样保留；写入只动目标想法块，其他行逐字节不变。
- 格式容错：缺 frontmatter / `format ≠ 1` → `format-version-unsupported`；`type ≠ idea-pool` → `parse-error`；只读模式绝不写入。

**字段与 ID**

| 字段 | 键/位置 | 必填 | 取值 | 缺省 |
|---|---|---|---|---|
| ID | 第 1 段反引号 | 是 | `I-YYYYMMDD-NN` | — |
| 名称 | 第 2 段 | 是 | 禁 `｜`/换行，≤200 | — |
| 详细描述 | 想法行下缩进续行 | 否 | 多行，≤10000 | 空 |
| 状态 | `状态：` | 是（总写） | 待实现 / 推进中 / 完成 / 放弃 | 待实现 |
| 成熟度 | `成熟度：` | 是（总写） | 低 / 中 / 高 | 低 |
| 分类 | `分类：` | 否 | 单行，禁 `｜`/换行，≤20 | 空 |
| 创建 | `创建：` | 是（总写） | `YYYY-MM-DD` | 今天 |
| 更新 | `更新：` | 是（总写） | `YYYY-MM-DD` | 今天 |
| 完成 | `完成：` | 状态=完成时 | `YYYY-MM-DD` | — |

**ID 不复用**：`$DSH_HOME/task-workbench/idea-ids.json` 记录每天已分配到的最大序号；创建时取「状态文件记录」与「文件内已有 ID」最大值 +1；删除后再建不复用。

**状态流转（仅人）**：四态互转；进入「完成」写 `完成：<今天>`，离开「完成」删除该字段；改状态同时更新 `更新：`。AI 越权 → `permission-denied`。

**删除**：硬删除整个想法块；写前备份 `想法池-<HHMMSS>.md`；无归档/回收站。

### 1.9 复盘数据契约（V3.0 新增）

**文件**：`data/复盘/日复盘.md`、`data/复盘/周复盘.md`、`data/复盘/月复盘.md`；三个单文件、不按月切；`type` 分别为 `review-daily` / `review-weekly` / `review-monthly`，`format: 1`。文件不存在 = 空记录；首次写入前自动创建骨架（`ReviewStore.ensureFile`，数据根未初始化时拒绝）。三个文件互相独立：某个损坏只影响该类型。

```markdown
---
title: 日复盘
type: review-daily
format: 1
created: 2026-11-05
updated: 2026-11-05
---

# 日复盘

> 每天一条，由人写；AI 只读，不改。

## 记录

- `2026-11-05`｜更新：2026-11-05 22:05
  今天完成了数据层与 UI。

  卡点：跨月材料要读上月分片。
```

**行语法**

```text
review_line = "- `" key "`" "｜" "更新：" "YYYY-MM-DD HH:mm" ( "｜" 未知字段 )*
key         = 日=YYYY-MM-DD ｜ 周=该自然周周一 ｜ 月=YYYY-MM
body        = 复盘行之后、以 2 个空格开头的连续行（空行写成 2 个空格，表示分段）
```

- 只有一个 H2：`## 记录`；区块缺失/重复 → `parse-error` 只读。
- 复盘行必须在第 0 列；正文固定 2 空格缩进，空行结束正文块（块间用一个空行分隔）。
- 正文内容可含 `｜`、`#`、`- ` 等（缩进后不会被误解析为字段/标题/新复盘）；写回时统一 2 空格缩进。
- 键格式非法 → warning 并原样保留该行；同一类型内键重复 → warning。
- `更新` 缺失/格式非法 → warning，按周期键回退一个可读值。
- 格式容错：缺 frontmatter / `format ≠ 1` → `format-version-unsupported`；`type` 不匹配 → `parse-error`；只读模式绝不写入。

**可写窗口（`core/review-window.js` 单一事实）**

| 类型 | 出现 / 可写窗口 | 复盘对象 |
|---|---|---|
| 日 | 仅「今天」 | 今天 |
| 周 | 本周一 → 周日 | 上一个自然周（周一→周日），不累积更早的周 |
| 月 | 当月最后一天 + 次月 1–3 日 | 当月；跨月补写时为上月 |

- 月末按实际天数（28/29/30/31），不用固定 31 号；跨年时 1 月 1–3 日补写上一年 12 月。
- 写入前 `isReviewWritable(kind, key, today)` 校验；窗口外 → `validation-error`（不是静默忽略）。
- 无 ID：周期键就是唯一键，因此**不需要 ids.json 之类的状态文件**。

## 3. 统一读写层与 AI 权限

### 3.1 唯一网关

- 三个域各有一个唯一网关：`TaskService`（任务）、`IdeaService`（想法）、`ReviewService`（复盘）。UI 走 `/tw/api/*`，AI 走 `tw_*` / `tw_idea_*` / `tw_review_*` 工具；各自调用同一 service、同一串行队列、同一 `baseHash` 锁、同一备份/回读/审计。**不存在第二条写路径。**
- 复盘域只读给 AI：`ReviewService` 同时承担人工写入与 AI 只读；写入入口按 actor 校验（非 user → `permission-denied`）。
- 三个 service 继承同一个 `WriteGateway`（`host/gateway.js`）：队列、`requestId` 幂等、审计逻辑只有一份；任务/想法行为与 V2.0 完全一致。
- actor 由服务端入口派生：UI 固定 `user`；工具从 `exec.agent.session.id` 取 `agent:<sessionId>`，不接受请求体自称。

### 3.2 权限矩阵（`service.js` / `idea-service.js` 单一事实）

| GET | `/tw/api/health` | 存活 + 版本 | 否 |
| GET | `/tw/api/bootstrap` | 任务设置/hash/计数 + `ideas`（想法 hash/计数/只读状态） | 否 |
| POST | `/tw/api/init` | 数据目录未初始化时创建目录 + 当月分片 | 是 |
| POST | `/tw/api/reload` | 外部改动后重载任务 + 想法（复盘板随今日视图请求刷新） | 否 |
| GET | `/tw/api/today` | 今日视图 | 否 |
| GET | `/tw/api/week?anchor=` | 本周视图 | 否 |

| DELETE | `/tw/api/tasks/:id` | 硬删除 | 是 |

## 4. 写入一致性

### 4.1 写流程（实际顺序）

```text
1. 入口派生 actor（UI=user / 工具=agent:<sessionId>）并做权限校验（想法改状态仅人）
2. 入参校验（字段、枚举、ID、长度）
3. 进入串行队列；按 requestId 查幂等表
4. 读目标文件（任务当月分片 / 想法单文件）→ sha256 → 与请求 baseHash 比对（不一致 → 409 external-change）
5. 内存模型上做块级变更（只改目标行/块；未涉及行逐字节不动）
6. 重新解析变更后的文本，校验结构、ID 唯一性
7. 备份当前文件 → data/备份/<date>/任务清单-<YYYY-MM>-<HHMMSS>.md 或 想法池-<HHMMSS>.md（失败则中止）
8. 写 tmp → fsync → rename → fsync 目录
9. 回读 → 与预期逐字节比对（不一致 → write-failed，附备份路径）
10. 更新缓存/hash；清理 >7 天备份；写审计；返回新 hash
```

- 任务：完成 = 改行 + 移块；撤销 = 移块 + 去完成日期；删除 = 移除行；都是同一次原子写。
- 想法：新建 = 区块末尾插入想法块；编辑/改状态 = 原地替换整块（元数据行 + 描述续行）；删除 = 移除整块；都是同一次原子写。
- 复盘：提交 = 周期键不存在时区块末尾插入、存在时原地替换整块（元数据行 + 缩进正文）；清空 = 移除整块；都是同一次原子写。窗口校验在队列内、读文件之前完成。
- 实现上 `appendTaskLine` / `removeTaskLine` / `replaceTaskLine`、`appendIdeaBlock` / `replaceIdeaBlock` / `removeIdeaBlock` 每次重新解析文本再定位，避免多次编辑后行号漂移。

### 4.2 队列、幂等、重复、备份、外部改动

- 单进程内每个域一条 FIFO（任务、想法、复盘各一条队列）；队列上限 50、单请求 5s → `queue-busy` / `timeout`。
- `requestId` 去重（最近 500 条，1 小时）；任务完成幂等：已完成再完成 = `noop`。
- 任务创建去重：同标题 + 同日期 60 秒内 → `duplicate-suspected`；UI 弹「仍然创建」，确认后带 `confirmDuplicate: true` 重试。
- 想法**不做** 60 秒重复检测（同一想法重复记录由人判断；AI 创建前先 `tw_idea_list` 查重）。
- `baseHash` 乐观锁：任务/想法各自独立 hash；写入前 hash 不一致 → `external-change`，不覆盖、不自动合并；UI 提示后重新加载。
- **外部改动检测（简化）**：主面板每 5 秒轮询 `/bootstrap` + 当前视图；页面隐藏、有弹窗或写入中时跳过；手动「刷新」/「重新加载」立即生效。**未使用 `fs.watch` / SSE**（留给后续）。
- **备份与恢复**：每次成功写入前备份当前文件，默认保留 7 天（`settings.backupRetentionDays` 可设 1–90；写入/启动时清理）；整体备份 = 拷贝 `data/`；恢复 = 手动把备份复制回目标文件 +「重新加载」。
- **想法文件生命周期**：不存在时读取按空池处理（不报错）；首次创建时自动生成骨架；格式损坏时想法域只读，任务域不受影响。

### 4.3 错误码

`validation-error` / `duplicate-suspected` / `permission-denied` / `not-found` / `file-missing` / `already-initialized` / `external-change` / `read-only` / `parse-error` / `format-version-unsupported` / `queue-busy` / `timeout` / `backup-failed` / `write-failed` / `rollover-failed` / `config-invalid` / `id-exhausted` / `internal-error`。

UI 行为：能就地提示的就地提示；`external-change` 提示并自动重载；`read-only` 禁用写控件并显示原因；`backup-failed`/`write-failed` 中止并显示备份路径。

## 5. 视图口径（UI / 工具 / 测试共用）

- **今日**：待办 = 未完成且「日期 <= 今天 <= 结束日期（单日任务结束日期=日期）」，跨周期任务在区间内每天出现；逾期 = 结束日期 < 今天（标「逾期 N 天」，天数按结束日期算）；今天已完成 = `完成 == 今天`。排序：优先级 → 全天在前 → 时间 → 文件行序。
- **本周**：包含今天的自然周（周一→周日）7 列；单日任务按 `日期` 落列；跨周期任务生成按周裁剪的 `spans`，UI 渲染为顶部摘要条（勾选 + 标题 + 起止日期 + 优先级色点，按优先级→结束日期排序、已完成置后），悬停 chip 时按 `startIndex/endIndex` 高亮对应日期列；今天高亮、之前淡显；只读查询，不复制任务、不建周文件。
- **任务总表**：`GET /tasks?includeCompleted=true` 取全部；前端按关键词 / 状态 / 优先级筛选；日期列显示「今天 15:00」或「11/5 09:30 → 11/9 18:00」；排序：优先级 → 日期 → 时间 → 文件行序。
- **想法池**：`GET /ideas` 取全部；前端按状态 / 成熟度 / 分类 / 关键词筛选；默认排序：状态（待实现→推进中→完成→放弃）→ 更新日期倒序 → 创建日期倒序 → 文件行序；停滞天数 = 今天 − 更新日期（仅未关闭；≥14 天显示「已放置 N 天」）；计数 `{ total, todo, doing, done, dropped, open }`（open = todo + doing）。
- **复盘板**：`dueReviewPrompts(today)` 决定出现哪些块（日固定；周整周；月仅在月末最后一天→次月 3 日）；每块带周期区间、窗口、已写状态、正文、更新时间、hash、只读原因；周/月块带材料（任务概况 + 上期日/周复盘）。材料由 `summarizePeriodTasks` / `reviewsInRange` / `weeklyReviewsOfMonth` 纯函数投影，跨月时 service 只读合并相邻月分片。
- **详情 / 编辑弹窗**：任务字段编辑 + 删除入口；完成勾选只在人操作时可用；想法弹窗含状态分段（仅人）+ 成熟度 + 多行描述 + 删除入口；不展示 AI 建议卡。复盘无弹窗表单（内联输入/展示），清空走确认弹窗。

## 9. 安装与运行

**典型安装形态**（本地开发用 `link:`）：

```text
~/.dsh/profiles/<profile>/package.json
  dependencies.dsh-task-workbench = link:/absolute/path/to/task-workbench
  dsh.profile.bundles += dsh-task-workbench
~/.dsh/profiles/<profile>/node_modules/dsh-task-workbench -> 本仓软链
```

### 9.1 安装方式

**从 npm（推荐）**：`dsh plugin --profile <profile> add dsh-task-workbench`，安装的是预构建代码，无需构建授权。

**从 GitHub / Release tarball**：

- Git 源码：`dsh plugin --profile <profile> add github:Zevin-Labs/task-workbench`（本插件无构建步骤、无 `prepare`，源码可直接运行，不需要 `allowBuilds` 授权）。
- 预构建 tgz：下载 [Release](https://github.com/Zevin-Labs/task-workbench/releases) 里的 `dsh-task-workbench-<version>.tgz`，`dsh plugin --profile <profile> add /path/to/<tgz>`。插件市场条目同时提供这个 tgz 作为兜底。

**本地目录 / Git**：DSH 插件页「添加插件」原生接受四种 spec：包名（可带版本）、Git 地址、压缩包、**本地绝对路径**。本插件无构建步骤，本地目录可直接装：

1. 目标机把本仓 clone 到固定路径（如 `~/Apps/task-workbench`）。
2. DSH 版本必须落在 `engines.dsh` 范围内（当前 `>=0.2.2-rc.1 <0.3.0`）；不符会在安装前报 `incompatible-version`，先对齐版本，不要盲目豁免。
3. 插件页 → 添加插件 → 输入仓库**绝对路径**或 `github:Zevin-Labs/task-workbench` → 安装。宿主会写 `link:` 依赖并加入 `dsh.profile.bundles`。
4. 首次打开「任务工作台」提示初始化；数据默认建在 `$DSH_HOME/task-workbench/data`。

**数据不跨机共享**：两台各写本机 `$DSH_HOME`。需要同步时拷 `data/任务清单/`、`data/想法池/`、`data/复盘/` 与 `data/备份/`。

**备选（目标机没有仓库）**：`npm run pack` 得出 `dsh-task-workbench-<version>.tgz`，插件页输入 tgz 绝对路径安装；数据同样默认在本机 `$DSH_HOME`，升级不丢。

> 若 `npm pack` 报 npm 缓存权限错误（`~/.npm/_cacache` 里有 root 所有权文件）：可临时 `npm pack --cache /tmp/npm-cache`，或修复缓存目录属主。

### 9.2 版本兼容策略

- `engines.dsh` 是唯一的宿主版本准入门槛：声明后忽略 `peerDependencies`，预发布版本参与匹配；空/无效范围视为不兼容，不匹配的组合包在启动时被**跳过**（不会导致整机启动失败）。
- 当前范围 `>=0.2.2-rc.1 <0.3.0`：开发与验收都在 0.2.2-rc.1 上完成；0.2.1 及更早的 client 契约未经实测，因此不声明支持。DSH 升到 0.3 前先在目标组合上验证 slot/API，再放宽上界。
- 本地路径安装会在 pnpm 跑之前直接读目标 `package.json` 的 `engines` 判定，失败不下载任何东西。

### 9.3 宿主与本地开发维护

- 首次安装后需触发一次插件重载：插件页关闭/开启组件，或重启 DSH App。
- 改 **host** 代码：关/开组件触发 recomposition，或重启 App；改 **client** 代码：刷新页面（客户端 HMR 热替换 `lib/client.js`）。
- 卸载：插件页卸载（或从 profile 依赖与 bundles 中移除）→ 重启；数据目录原样可读。
- 本地开发想沿用仓库 `data/`：把 `$DSH_HOME/task-workbench/settings.json` 的 `dataRoot` 指到仓库内 `data/`（已 gitignore）；换路径时把旧数据拷到新路径即可。

## 10. 与原设计的偏差（如实记录）

| 原设计 | 实际 | 原因 |
|---|---|---|
| client 原生 React（原本就是） | ✅ 保持原生 React，无 iframe | 官方 practices；主题/语言可继承 |
| `fs.watch` + SSE 推送外部改动 | 改为 UI 5s 轮询 + 手动重载 | V1 少一个长连接与 watcher 生命周期问题；体验够用 |
| 设置写接口 `PUT /settings` | 未实现；设置只读展示 | V1 只有一个数据根，不需要在 UI 改 |
| Dock 数字徽章 | 未做 | `sidebar.panellist` 目录未提供 badge 约定，V1 不做 |
| `settings.section` 设置页 | 未做；设置放在面板内弹窗 | 减少 slot 面积与权限/生命周期复杂度 |
| 客户端接 locale 服务 | 中文硬编码 | 单用户；locale 留后续 |
| 按月分片 + 历史只读 | ✅ 保持 | — |
| 调研建议「想法与任务共表/共用 ID 空间」 | 实际**分文件、分 ID 前缀、分 service** | 任务按月分片有月切生命周期，想法是长期资产；共表会被月切/历史只读规则破坏。逻辑上仍同属一个面板、共用 gateway/审计/备份 |
| 想法列表只读时返回 `{readOnly:true}` 载荷 | 实际 `GET /ideas` 抛 409 `read-only`（与任务视图一致）；client 双兜 | 文件损坏时不展示半解析数据；bootstrap 另带 `readOnly` 供横幅 |
| 想法创建 60 秒重复检测 | 未做 | 想法重复更常见且判断主观；AI 先 list 查重，人可删除 |
| 想法 → 任务转化 | 未做 | 跨模块关联/回写语义复杂，单独版本评估 |
| `WriteGateway` 公共抽取 | TaskService 改为继承，行为不变 | 三个域共用队列/幂等/审计，避免复制并发代码；既有用例不改动、全通过 |

| 复盘块顺序（日→周→月） | 暂定，未做可配置 | 最小实现；截图验收后再按手感调整 |
